# Libraries for the next architecture

Status: proposal, 21 November 2026. Companion to [../reframing.md](../reframing.md) (§3 and §4 are the plan this serves).

## How to read this

- Every version below was read from the registry on 21 November 2026: crates.io API for crates, `registry.npmjs.org` for npm packages, the GitHub API for repositories (archived flag, last push, releases). Nothing comes from memory.
- "Released" is the publication date of the stated version. "Pushed" is the last push to the default branch of the repository, shown when the last release is old and the repository is the better signal of life.
- UNVERIFIED means a lookup failed or the claim was not checked; the cause is written next to it.
- Dependency versions in this repository are pinned exactly (no `^`); the versions below are what to pin on first use.
- Licence target: Apache-2.0 for the SDK side, AGPL-3.0 for the engine and `anvil`. Everything chosen is MIT, Apache-2.0, ISC, BSD or a dual of those, except the points listed in E. `scripts/licenses.ts` allows MIT, Apache-2.0, BSD-2/3, ISC, 0BSD, BlueOak, Python-2.0, CC0 and Unlicense; MPL-2.0 is not in the list (see D). It only reads `node_modules`; Rust needs its own check (`cargo-deny`, row B-39).
- Rust toolchain is 1.93.0 (`rust-toolchain.toml`). The MSRV of the chosen core crates, from crates.io: tokio 1.85, hyper 1.63, axum 1.80, reqwest 1.85, rusqlite 1.89, object_store 1.85, capnp 1.87, opentelemetry 1.75, rustls 1.71, clap 1.85, toml 1.85, notify 1.91, opendal 1.91. All fit.

## D. Deliberately not used

| Library or approach                                       | Why not                                                                                                                                                                                                                                                                            |
| --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Protobuf, gRPC, WIT or Cap'n Proto as the contract format | Contracts are TypeScript interfaces plus a written semantic specification and conformance tests; a schema language would be a second source of truth. Cap'n Proto appears only where workerd demands it (B-16). The WASI storage interfaces the plan mentions are still proposals. |
| An ORM (Drizzle, Prisma, TypeORM)                         | Kysely is already the typed layer; `defineModel` generates tables, so an ORM would own a second schema.                                                                                                                                                                            |
| Redis, Valkey, NATS                                       | The `kv`, `queue` and `schedule` contracts are met by SQLite on a single node; another service raises the cost of "a machine or a VPS".                                                                                                                                            |
| Postgres as a hard dependency                             | Same reason; also rules out DBOS. A Postgres provider for `database` may exist later; it must never be required.                                                                                                                                                                   |
| Litestream embedded as a library                          | It is Go; we supervise it (B-12).                                                                                                                                                                                                                                                  |
| libsql or `turso` as the SQLite engine                    | The fork's server is in maintenance (last release 2025-02-14) and the rewrite is pre-1.0 (B-7).                                                                                                                                                                                    |
| sqlx                                                      | Async facade over a thread, no backup API, compile-time query checks we do not use.                                                                                                                                                                                                |
| apalis                                                    | Our queue semantics (chaos redelivery, workflow journal, per-tool files) differ; its SQLite crate is mid-migration (B-14).                                                                                                                                                         |
